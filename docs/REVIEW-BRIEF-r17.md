## 2. 隔离验收实例（本轮最大的一件）

**入口**：`tools/iso-instance.mjs`。**一条命令跑完整个流程**（不需要任何密钥环境变量）：

```powershell
node tools/iso-instance.mjs run --name poc5 --root D:\DeepSeek\dsh-iso\poc5 `
  --port 19412 --cdp 19512 --baseline iso-r10 --repeat 3
```

流水线：准备（插件副本 + profile + 测试图库）→ 起宿主（**本进程的直接子进程**）→ 等端口 →
**隔离证明（不成立即中止）** → 设测试底图（先于浏览器）→ 起隔离浏览器 → 装标记图（进隔离库）→
selftest → capture → compare（`--repeat N` 可连跑）→ A 级变异 → 覆盖审计 → 收尾（杀子进程）→
复核生产未被碰。

**绑定是显式的环境变量**（不是"但愿连对了"）：`DSH_HOME` / `VB_GUI_HOST` / `VB_CDP_PORT` /
`VB_VIEWPORT` / `VB_SKIP_ONBOARDING` / `VB_PLUGIN_DIR`。

**隔离证明（硬门槛）**：插件 `/bga/wallpapers.json` 的 `dir`/`writableDir` 都在隔离根下、
只看到测试分类、状态头可用、生产 `settings.json` 哈希不变。证明不了 ⇒ 杀掉自己起的进程、拒绝继续。

- **判活标准是"有没有 HTTP 响应"**，不是"响应是否 ok"：我原来先请求 CDP 专用路径 `/json/version`，
  DSH web 端口对它返回 **404** ⇒ `fetch` 不抛异常 ⇒ `r.ok===false` 直接判"没在听"、**永不回退到 `/`**
  ⇒ 宿主明明起来了却被脚本**自己杀掉**。我据此写下的"Windows Job 回收宿主"是**错误归因**，已更正。
