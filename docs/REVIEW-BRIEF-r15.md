## 1. 四处**还原类**真缺陷（都属验收约定第 1 项「设置保护」）

这一项的口径是：**验收工具结束后必须完整恢复用户状态**（原话："壁纸被验收工具永久换掉"属必须检出的错误）。

### 1.1 钉过图、但"全部状态被拒绝"那一轮把用户底图永久留在基准那张

- **现象**：我卸载标记图之后，8 个状态全部报"图片未就绪"；查磁盘发现用户 `settings.json` 的
  `wallpaper` 正指向已被删除的 `_验收标记图/marker-960x540.png`。
- **根因**：`restoreRotation` 里回填 `wallpaper/zoom/focus/imageFraming` 的条件是
  `if (wallpaperSwitched)`。而 `wallpaperSwitched` 只在 `switchWallpaperTo()`（标记图状态）里置真。
  当**所有状态都在换图之前就被拒绝**（本例：页面状态不符 ⇒ 全拒），从未走到换图
  ⇒ 条件为假 ⇒ 不回填。可是 `pinWallpaper()` 在每轮 capture/compare 开头**已经写过**
  用户的 `wallpaper`（钉成基准那张）⇒ 那次写入没人还。
- **修法**：新增模块级标志 `wallpaperPinned`，`pinWallpaper()` 确认成功后置真；
  回填条件改成 `if (wallpaperPinned || wallpaperSwitched)`。
  语义是"**我们改过就必须还**"，而不是"走到某一步才还"。
- **证据**：修后连跑 3 次 compare，每次结束后磁盘都是用户原值（`高清/洁西卡金蜜.png`，含完整字段）。

### 1.2 `autoOn` 被写死还原成 `true`，把用户的"关"翻成"开"

- **现象**：跑完一轮 compare，磁盘 `autoOn` 从 `false` 变成 `true`。
- **根因**：`const merged = { ...now, autoOn: true }` 写死。这条只在"冻结点原本开着轮播"时才对。
- **修法**：`const wantAutoOn = want.autoOn === true` 并写回它；
  磁盘/内存校验也改成与 `wantAutoOn` 比较（原来写死 `=== true`，会把"正确地还原成 false"判成失败）。
- **证据**：修后连跑 3 次，结束后磁盘 `autoOn` 始终等于冻结点原值。

### 1.3 功能套件在 `autoOn=true` 时还原后又被轮播换走

- **现象**：第 6 项套件跑完，用户底图变成了套件测试用的那张（标记图）——这也是
  §1.1 那条链的上游诱因。
- **根因**：单段还原"写快照 → reload"。若快照本身 `autoOn=true`，还原瞬间轮播立刻可能再换一张
  并落盘，把刚写回的底图覆盖掉。
- **修法**：**两段式还原**——先连 `autoOn` 一起关掉写快照并确认底图落定，再把原 `autoOn` 还回去。
- **证据**：套件跑前/跑后磁盘底图一致（`高清/洁西卡金蜜.png`）；新增断言
  "★ 底图对象字段完整（没被写残成 `{cat:…}`）"。

### 1.4 换图写入用"完整格式"，但字段取自 `wallpaperIdent` ⇒ `url: undefined`

- **现象**：capture 时状态 04 报
  `✗ 切换底图后画面背景不是 marker-960x540.png（实际 读不到壁纸 URL）` ⇒ 拒绝录基准（exit 4）。
  诊断显示：**磁盘里 `wallpaper.file` 是对的、客户端内存探针里也是对的**，唯独 `body::before`
  里没有壁纸 URL。
- **根因**（本轮我自己引入又自己抓出来的）：为了让写入值是插件完整形状
  （`id/cat/file/name/url/hd/tags/no/size`），我把字段来源写成 `ident` ——
  但 `wallpaperIdent` 只有 `{cat, file, zoom, focus}`，**没有 `url`** ⇒ 写进去 `url: undefined`
  ⇒ 插件内存里有对象、却无法据此构造图片地址 ⇒ 不画。
- **修法**：字段改从**上面刚从 `/bga/wallpapers.json` 找到的完整条目 `entry`** 取
  （`url/hd/tags/no/size` 全部来自它）。
- **证据**：修后 `capture audit-r29` **exit=0**（8 状态全部录成）。
- **备注**：这条的审阅价值在于"**数据全对但没渲染**"这一症状很容易把人带去渲染层找错方向。

## 2. 两个**环境前提**（工具现在自动处理，属于"以前靠运气"）

### 2.1 后台标签页会让画面确认假失败

- 插件在 `document.hidden` 时**故意不画壁纸**（`wallpaperBackgrounded()` → `suspendWallpapers`，
  client.js:840 附近），也**故意不装轮播定时器**。
- 实测本机 GUI 标签页默认 `document.hidden === true` ⇒ "钉图/换图后画面确认"读不到壁纸 URL
  ⇒ 直接拒绝录基准（exit 4）。**之前若干轮偶尔成功，只是因为那几次标签页恰在前台**
  —— 属于"看着在跑、其实依赖运气"。
- **修法**：capture/compare 开工时 `Emulation.setFocusEmulationEnabled(true)`（收尾关掉）。
  复现命令：`node tools/visual-baseline.mjs capture <名>` 的日志里现在有
  `页面可见性: 已用 focus 模拟置为可见+聚焦`。

### 2.2 渲染确认从"睡固定时间单查"改成"轮询等待 + 一次刷新重试"

- 底图大小差别极大（实测用户某张 `高清/洁西卡金蜜.png` 是 **53 MB**，标记图只有 14 KB），
  reload 后解码大图要好几秒 ⇒ 固定 3.5 秒单查会假失败。
- **修法**：`waitRenderedWallpaper(want, timeoutMs=15000)` 轮询（读 `body::before` 与
  `html::before` 的 `backgroundImage`，解析 `/bga/wallpapers/` 后的 basename 精确比对）；
  换图路径失败后**再刷新一次**并给 20 秒。
- **注意**：判据仍是"精确 basename 相等"，不是子串匹配（子串匹配会被 `want='x.png'` 对上
  `http://x/...` 而假通过 —— 这个坑更早的轮次踩过）。

## 3. 新增**页面状态守卫**（含一次"守卫永不生效"的自纠）

- **背景**：`[data-composer-card]`（状态 07/08 的"主体表面"锚点）在**首页/「新会话」页**
  与**打开着会话**两种状态下是**两个不同位置的元素**（实测 `456,397–1244,511` vs `391,679–1309,777`）。
  页面状态不一致时，工具原来会报"覆盖不足：高度 X vs Y"——**是响的，但信息不达意**，容易被当成像素问题。
- **修法**：锚点测量里新增 `hasConversation`（`document.querySelectorAll('[class*="_bubble"]').length > 0`），
  录制时存进基准 `pageState`；比对时不一致就报
  `页面状态与录制时不一致：录制时**在首页/新会话页**，现在是打开着会话 ⇒ …先回到首页/新会话页再重跑。`
  并计为不可比对（`exit 1`）。
- **⚠️ 自纠**：这守卫**第一版永不生效**。`prepareState(s, …)` 的 `s` 是 `STATES` 里的条目，
  而基准的 `pageState` 在**另一个对象**（manifest 条目）上，写成 `s.pageState` 恒为 `undefined`。
  已改成显式传参 `prepareState(state, false, rel, pluginRel, s.pageState || null)`。
  **这是本轮最值得审的教训**：加守卫后必须**故意造一个它该拦住的场景**去验，否则等于只加了段注释。
- **证据**（真机）：会话页下 compare ⇒ 8 个状态全部报该消息、exit=1；点"新会话"回首页后再跑
  ⇒ `8 一致 / 0 有差异`。

## 4. 覆盖对象的两处口径调整（都带正反例）

### 4.1 主体表面（07/08）改成"只比外圈 8px、内文整块屏蔽"

- **根因**：`[data-composer-card]` 是宿主输入框容器，里面是**宿主内容**（占位文字、上下文 chip），
  会随"新会话/打开会话"变 —— 实测同属首页状态，点一次"新会话"后该区域就报
  **1070px / Δ157 的假回归**。插件对这个表面只贡献 `background`/`border`
  （client.js 的 `body[data-ds-dark-theme] [data-composer-card]{background:…}`）。
- **修法**：`masks` = 该矩形内缩 8px 的整块（即只留外圈参与比较）。
- **代价用断言钉住**（`tools/verify-oracle-geometry.mjs`，新增 3 条）：
  · 整块底色 40→90 ⇒ **必须检出**；
  · 内文区单独改色 ⇒ **检不出来**（有意，如实钉住）；
  · 外圈改色 ⇒ **必须检出**（证明屏蔽没吃掉插件影响）。

### 4.2 覆盖审计的点位搜索修正

- 旧写法只判 `y` 越界、不判 `x` ⇒ 会一路挪到**框外**植入变化（实测 png 侧 `x=1452` 而框到 `1451`）
  ⇒ 必然"漏检"，是**测试自己位置选错**。
- 且 07/08 现在只剩**8px 外圈**，10×10 补丁在框内**根本放不下** ⇒
  正确做法是**如实跳过这一条**，不是报漏检（那是把有意的盲区当缺陷）。
- **修法**：框内网格搜索"整块不与任何屏蔽框相交"的位置；找不到就打印
  `⏭️ …比较区去掉屏蔽框后放不下 10×10 ⇒ 本条不适用，跳过`。

## 5. 第 6 项"动效节点级"从**未测**变**已测**

- **为什么以前是未测**：动效节点注入在宿主 slot `conversation.composer.dock`（client.js:3105），
  **首页/「新会话」页那个 slot 不挂** ⇒ 节点恒为 0，无法区分"slot 没挂"与"动效坏了"。
- **修法**：套件新增 `ensureConversationOpen()` —— 自动点开侧栏里"**带相对时间**"的那一项。
  判据刻意**不写死工作区名字**（`/刚刚|[0-9]+\s*(秒|分钟|小时|天|周|月)前?$/`），
  因为侧栏是虚拟化树 `[role="treeitem"]`，会话行自带相对时间、工作区分组行没有。
  收尾再点回原来选中的那一项（找不到"新会话"时退回应用自己的"新会话"按钮）。
- **证据**（真机）：`effect=firefly` ⇒ **41 个装饰节点**且两次采样位置不同
  （`[540.4,737.7]→[576,733.8]`）；`effect=off` ⇒ 节点 0 且再采样仍 0。
  套件总计 **13 通过 / 0 失败 / 0 未测**。
- **一条失败的判据（也值得审）**：我先试过用"样式表里有没有 `.bga-fly`"当替代信号，
  实测 `effect=firefly` 与 `effect=off` 两份样式表**几乎完全相同**（动效 CSS 常驻、只差 33 字节），
  开关只体现在是否渲染节点 ⇒ **那个判据根本不能区分对错**，已删掉。

## 6. 其他工程性加固

- **`readState` 反引号守卫**：这些页面表达式都是模板字符串拼出来的。我在**模板内的中文注释**里
  写过反引号 ⇒ 模板被提前闭合 ⇒ 后面的方括号内容被当成 JS 求值（报 `data is not defined`），
  而 `node --check` 因为**仍是合法语法**照样放行 —— 本轮又踩到一次。
  现在 `readState` 见到表达式里含反引号**直接抛错**。
- **注入自愈**：`prepareEnvironment` 原来"`#vb-backdrop` 已存在 ⇒ 视为垫底未生效 ⇒ 拒绝录基准"。
  上一轮异常退出留下的残留会把**后续每一轮**都堵死，且原因看不出来。
  改成**先删旧的再重建**（顺带保证元素属性确实是本次注入那份）。
- **输入框光标冻结**：新增 `input,textarea{caret-color:transparent!important}`。
  07/08 锚在宿主输入框上，里面有个会闪的光标 ⇒ 抓图时一个是亮点一个是底色，
  表现为 CSS `x471, y412–430` 的 **1px×19px 竖线、Δ183**（连跑 3 次都复现）。属宿主自身动效，
  与既有的"停插件动画"同源。
- **离线套件跟随实现**（每次改函数签名都要跟着改，否则假失败）：
  · flow 沙箱补切 `waitRenderedWallpaper`，并补 `wallpaperPinned` 变量、补桩分支、

## 8. 我**不**声称的事（本轮新增缺口，已写进约定排除范围第 10 条）

**钉大底图时"壁纸可见区域"不稳** —— 同样 8 个状态、同样环境：

| 钉的底图 | 连跑 3 次 |
|---|---|
| 小图（验收标记图，14 KB）→ `audit-r28` | **3 次都 8/8 零差异** |
| 用户当时的大图（`重返未来1999/野树莓1.png`，4.8 MB）→ `audit-r29` | 只有 1 次 8/8；另两次报 01/02/05/06（侧栏带，露出壁纸）**6% / Δ230**、08（半透明卡片外圈，透出壁纸）**1% / Δ7** |

- 怀疑机制：插件会把底图**升级到 large 变体**（日志里见过 `?sz=large`），
  "是否已升级"取决于缓存/时序 ⇒ 壁纸可见区域的像素在两次运行间不同。
- **当前口径**：录基准时钉**小图**可稳定复现；钉大图时该区域不可信。
- **未做的事**：**没有**去动容差、**没有**把该区域屏蔽掉来换绿色。
- 结论：**在此之前不能声称"大图下也 8/8"。**

其余长期缺口（未变）：`glass`/`styles`/`imageFraming` 无法自证；原始基准已丢（不能声称语义等价）；
主题只覆盖三个宿主表面（`--dsw-alias-bg-layer-2/3/4` 无独立锚点）；01/02 只覆盖 orb 附近一条带；
动效层被冻结（动画本身靠功能验证）；**只跑了 Chrome，Edge 未跑**；
一条基准只在**它自己的 CSS 视口尺寸**下对像素有效（`background-size: cover` ⇒ 视口一变底图重裁）。
